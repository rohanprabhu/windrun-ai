# Cloud DNS Authoritative Zone Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove DigitalOcean from Pulumi by making Google Cloud DNS authoritative for `windrun.ai.` while keeping registrar nameserver changes manual.

**Architecture:** The foundation stack will create one shared-project public Cloud DNS managed zone for `windrun.ai.` and put all application, staging, preview, certificate validation, CAA, and preserved business records into that zone. Pulumi will output the assigned Cloud DNS nameservers for the human registrar update. DigitalOcean provider/resources/config/dependency/docs will be removed.

**Tech Stack:** Pulumi TypeScript, `@pulumi/gcp`, Google Cloud DNS, Google Certificate Manager, Vitest, Node test runner, pnpm.

## Global Constraints

- Do not use Composio or Composio accounts.
- Do not add any registrar API token, service-account JSON key, GitHub secret, or static GCP credential.
- All routine DNS records must be managed by Pulumi in Google Cloud DNS.
- The registrar nameserver update remains a manual administrative step.
- Do not cut over registrar nameservers until Cloud DNS contains all required current `windrun.ai` records.
- Preserve Google Workspace MX, SPF, DKIM, DMARC, and domain-verification records before cutover.
- Continue using `rohan@windrun.ai` for local Google bootstrap boundaries.
